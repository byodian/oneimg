# Use a finite scene-neutral Block Catalog

Every Scene will compose the same finite Block Catalog, with Scene Bindings mapping advisory Slots to common Blocks rather than introducing scene-specific content types. A Document has one Active Scene; each Slot may map an ordered list of Blocks, each Block may fulfill at most one Slot, and unbound Blocks remain valid. Repeating Block entries use fixed scene-neutral structures whose editor labels may adapt to the Scene. Only Section may contain Blocks and nesting stops after one level; User Templates cannot add Block kinds, while unsupported future kinds remain preserved as Unknown Blocks. This trades early plugin extensibility and arbitrary composition for portable content, predictable migrations, consistent editing and export, and a smaller interface for people without design expertise.
