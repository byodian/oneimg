# OneIMG Package streaming and validation spike

This note records the Slice 03 implementation for Issue #29. The Package Module now preflights replayable Document and Asset sources, computes SHA-256 and CRC32 incrementally, and exposes a `ReadableStream<Uint8Array>` for the ZIP archive. It never constructs the complete archive Blob before the caller consumes the stream.

The v1 ZIP adapter deliberately writes stored entries rather than accepting a compression implementation whose decompressor has not passed the package resource limits. Its producer honors `ReadableStream` demand and slices output into bounded chunks, so a slow consumer does not cause the complete archive to accumulate in the stream queue. The reader accepts only that bounded stored form, validates normalized ASCII paths, local and central directory agreement, declared byte lengths, SHA-256, CRC32, media signatures, JSON graph relationships, executable declaration keys, and aggregate resource limits before returning an inspection or Imported Draft. A supplied Render Source must declare a versioned conversion revision so the recovery path can explain why it exists.

Import remains a candidate-only operation in this spike: it returns an `Import Report`, immutable package metadata, copied Asset Blobs, and newly issued Draft/Document/Asset identities. Source and caller-reserved identities are rejected when a custom identity factory attempts to reuse them. Snapshot references using the declared Asset-reference keys are remapped to the newly imported Assets. It does not replace an active Draft, create a live file binding, or commit to a Local Repository. Unknown Blocks and Unresolved Assets remain represented in the document and report rather than being silently discarded; a newer format version returns an explicit Recovery Draft result instead of being imported as if it were complete.

Scenario coverage exercises streaming progress, semantic Document and Asset round-trip, independent import identities, nested Asset-reference remapping, path traversal, duplicate entries, digest tampering, media spoofing, executable declarations, newer-format recovery, and bounded Document/entry rejection. ZIP byte identity is intentionally not asserted.
